## Investigation Notes
- `scripts/tools/` does not exist yet in the repository, so Task 2.1 will establish the initial tool location as well as the first manifest-tool implementation/tests.
- The design defines a uniform `{Tag, Version, [Fields]}` root contract across `sdk_manifest`, `project_manifest`, and `firmware_manifest`.
- Existing shell code does not yet invoke `manifest-tool`; the current repo surface only references manifest filenames and future integration points.

## Key Decisions
- Established the initial `scripts/tools/manifest-tool` as an Erlang escript,
  matching the design direction instead of introducing a bash placeholder.
- Scoped the first task to the root-reader foundation by implementing one
  explicit command:
  - `validate-root --manifest PATH`
- Kept future public commands (`get`, `verify`, `merge`, `hash`,
  `create-project`) out of scope for now rather than shipping partial behavior
  that would claim more of the documented contract than this task covers.
- Made the shared reader enforce the common manifest-root contract:
  - exactly one Erlang term per file,
  - tag must be one of `sdk_manifest`, `project_manifest`,
    `firmware_manifest`,
  - version must be a binary,
  - fields must be a list,
  - every top-level field entry must be a tuple.
- Split failures into stable categories now so later commands can build on
  them:
  - exit `2` for structural/root-shape errors,
  - exit `3` for parse/read errors.

## Unexpected Issues And Resolution
- The first shell tests invoked the escript through the repo's default `escript`
  resolution path, which hit the local `asdf` shim and failed because this repo
  has no `.tool-versions` file selecting Erlang.
- Updated the test helper to resolve a concrete installed `escript` binary
  under `~/.asdf/installs/erlang/.../bin/escript` when the shim is detected,
  while still allowing an explicit `ALLOY_TEST_ESCRIPT` override. This keeps
  the tests deterministic without changing repo-wide tool-version policy in
  this task.
