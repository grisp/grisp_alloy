## Objective
- Implement the `alloy build sdk` target loop so one shared Smelterl plan drives
  per-target `smelterl generate` calls for auxiliaries first and the main
  target last.

## Key Decisions
- Use `build_plan.env` only as shell loop metadata; every target still invokes
  `smelterl generate` with the shared `build_plan.term` path so Alloy does not
  invent a second plan source of truth.
- Derive main-vs-auxiliary loop behavior from `ALLOY_PLAN_MAIN_TARGET` and the
  ordered `ALLOY_PLAN_TARGET_IDS` list, keeping the shell layer focused on
  orchestration rather than plan parsing.
- Create the durable target-local directory skeleton now
  (`targets/<TARGET_ID>/workspace`, `br2_external/`, generated defconfig, and
  `alloy_context.sh`) so later Phase 5 tasks can add hook wrappers and
  Buildroot execution in place.
