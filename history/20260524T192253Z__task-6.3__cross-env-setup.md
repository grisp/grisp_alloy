# Task Context: Task 6.3 - Cross-compilation environment setup

## Started
- Timestamp: 2026-05-24T19:22:53Z
- Repository: grisp_alloy
- Planning item: Task 6.3 (`docs/PLANNING.md`)

## Goal
Refactor `alloy build project` environment setup to use context-driven, modular layering:
1. source SDK context (`alloy_context.sh`) as authoritative `ALLOY_CONFIG_*` input,
2. set generic cross-compilation environment from shared utilities,
3. apply plugin/runtime-specific environment setup (Erlang/Elixir) without forcing unrelated plugin requirements.

## Implemented
- Refactored `scripts/utils/env_utils.sh` into layered setup APIs:
  - `setup_cross_env`: generic toolchain/sysroot/pkg-config environment only.
  - `setup_erlang_runtime_env`: Erlang runtime/tooling exports (`TARGET_ERLANG`, `HOST_ERLANG`, `HOST_REBAR3`, OTP/include/link vars).
  - `setup_elixir_runtime_env`: Elixir host tooling export (`HOST_MIX`).
- Updated `scripts/commands/build-project.sh` to:
  - source `env_utils.sh`,
  - call `setup_cross_env` for all project types,
  - apply runtime-specific setup only for `erlang` / `elixir` plugin types.
- Updated `scripts/grisp-env.sh` compatibility flow to call `setup_erlang_runtime_env` after `setup_cross_env` so legacy sourced environment behavior remains Erlang-ready.
