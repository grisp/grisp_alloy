## Key Decisions

- `scripts/commands/build-sdk.sh` now treats `ALLOY_SDK_PLAN_FILE` and
  `ALLOY_SDK_PLAN_ENV_FILE` as the command-owned names for the two plan
  outputs under `ALLOY_SDK_PLAN_DIR`.
- Alloy passes the documented literal extra-config placeholders required by
  later generated contexts and defconfigs. It intentionally does not pass
  `ALLOY_MOTHERLODE` as a CLI extra-config override; Smelterl injects that key
  itself per its design contract.
- Plan artefacts are validated as non-empty immediately after Smelterl returns
  so later target generation cannot silently consume a missing or empty plan.

## Unexpected Issues And Resolution

Fixture command tests originally allowed inherited `ALLOY_ROOT` and
`ALLOY_ROOT_DIR` to flow into copied `build-sdk.sh` commands. In environments
where those variables are exported, the fixture command resolves the real
repository root and real Smelterl version instead of the fixture root and
fixture Smelterl version. The fixture invocations now explicitly clear both
variables so the copied command tests are hermetic.

## Validation Notes

Focused coverage asserts the exact plan handoff surface: product, motherlode,
output paths, literal SDK/firmware placeholders, and absence of an
`ALLOY_MOTHERLODE` CLI override. A real cached Smelterl run against builtin
`smoke_product` produced both plan artefacts successfully.

The final full gate passed. Its shellcheck phase still reports non-blocking
warnings in the legacy repository-root `build-firmware.sh`; those warnings are
outside this task's touched files and were not changed here.
