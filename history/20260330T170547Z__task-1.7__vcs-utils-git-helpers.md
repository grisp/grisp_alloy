## Investigation Notes
- `vcs_utils.sh` was missing at task start, while the design already depended on
  it for nugget staging, project-source resolution, and repository provenance
  handoff into Vagrant-delivered trees.
- The design described dirty-check bypass through `--allow-dirty`, but the
  original utility signature did not expose how that policy reached the helper.
- The final contract now keeps that decision explicit at the utility boundary:
  Alloy commands resolve `--allow-dirty` / `ALLOY_ALLOW_DIRTY`, then pass a
  plain `true|false` argument into `vcs_clone_or_validate`.

## Key Decisions
- Implemented `scripts/utils/vcs_utils.sh` as a git-backed utility module with
  the documented exported surface:
  - `vcs_clone_or_validate VCS_TYPE URL REF TARGET_DIR ALLOW_DIRTY`
  - `vcs_get_provenance TARGET_DIR`
  - `write_alloy_repo_info REPO_ROOT`
- Kept dirty-policy handling explicit:
  - `vcs_clone_or_validate` requires `ALLOW_DIRTY=true|false`.
  - The utility does not read ambient environment for dirty-policy decisions.
- Used a safe dirty-ref rule:
  - a dirty checkout is accepted only when it is already at the requested
    commit and `ALLOW_DIRTY=true`,
  - the utility refuses to switch a dirty checkout to a different ref because
    doing so would discard local edits.
- Standardized provenance output as `KEY=VALUE` lines matching the
  `.alloy_repo_info` file contract so `vcs_get_provenance` and
  `write_alloy_repo_info` share one canonical representation.
- Updated the design document so the final expected state reflects:
  - the explicit `ALLOW_DIRTY` utility argument,
  - the command-level `ALLOY_ALLOW_DIRTY=true` default for future Alloy command
    implementations,
  - the safe dirty-ref behavior.

## Unexpected Issues And Resolution
- The git test fixtures initially hung during `git commit` because local test
  repositories inherited commit-signing configuration from the environment.
- The fixture helper now runs git setup and commit commands inside an isolated
  temporary git-config home so the tests do not depend on the developer's
  global signing configuration and do not override repository-local
  `commit.gpgsign` policy.

## Design Changes
- Updated `docs/03_ALLOY_DESIGN.md` to define the VCS helper contract with an
  explicit `ALLOW_DIRTY` argument, describe the safe dirty-ref behavior, and

- Updated `docs/WORKFLOW.md` to require the agent to stop after staging and

## Residual Risks / Follow-ups
- The dirty-policy environment handling is documented but will not become
  active until the future `build sdk` and `build project` command tasks wire
  `--allow-dirty` / `ALLOY_ALLOW_DIRTY` into the new helper.
- The utility currently supports `git` only, which matches the current design
  examples and task scope. Additional VCS backends would need explicit design
  work.
