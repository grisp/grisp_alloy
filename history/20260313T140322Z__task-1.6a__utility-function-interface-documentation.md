## Investigation Notes
- The sourceable utility modules now hold a growing amount of reusable shell behavior, but most functions currently require reading implementation details to understand arguments, stdout/stderr conventions, environment expectations, and failure behavior.
- The workflow doc currently emphasizes testing and traceability but does not explicitly require interface comments for exported shell utility functions.

## Key Decisions
- Added compact interface comments directly above the reusable function surface in:
  - `scripts/utils/common.sh`
  - `scripts/utils/console_utils.sh`
  - `scripts/utils/debug_utils.sh`
  - `scripts/utils/file_utils.sh`
  - `scripts/utils/env_utils.sh`
- Standardized the comment content around the same contract dimensions:
  - purpose,
  - arguments,
  - stdout/return behavior,
  - environment inputs and side effects,
  - error handling.
- Updated `docs/WORKFLOW.md` so this becomes an explicit requirement for future sourceable utility modules, and so callable interface documentation must be updated whenever behavior changes instead of drifting over time.

## Unexpected Issues And Resolution
- `scripts/utils/common.sh::resolve_script_dir` changes directory during execution, which is harmless in current command-substitution use but easy to miss when reading the function in isolation.
- The new comments call out that side effect explicitly so future callers know to keep using command substitution or otherwise account for the cwd change.

## Design Changes
- Updated `docs/WORKFLOW.md` to require compact interface comments for exported/reusable functions in sourceable shell utilities and to require same-change documentation updates whenever reusable function/interface behavior is modified.

## Residual Risks / Follow-ups
- This task documented the currently implemented utility modules only. Future sourceable modules should follow the workflow rule from the start so documentation quality does not regress.
- The comments describe current contracts; if later tasks change argument or environment behavior, the comments must be updated in the same commit as the implementation.
