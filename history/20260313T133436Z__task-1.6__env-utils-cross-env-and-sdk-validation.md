## Investigation Notes
- The design defines `validate_sdk_dir`, `setup_cross_env`, and `validate_release_target_arch` as the public surface.
- The current implementation still sources `scripts/grisp-env.sh`, which mixes SDK discovery, environment export, prompt mutation, and legacy `GLB_*` assumptions.
- The new utility should reuse the legacy variable behavior where still needed by current callers, while moving toward the design-defined API and fast-fail dependency checks.

## Key Decisions
- Implemented `scripts/utils/env_utils.sh` as a new sourced utility module on top of `scripts/utils/common.sh`, with the design-defined public API:
  - `validate_sdk_dir`
  - `setup_cross_env`
  - `validate_release_target_arch`
- Made triplet discovery prefer `ALLOY_CONFIG_TARGET_ARCH_TRIPLET` and fall back to scanning `host/bin/*-gcc`, preserving compatibility for SDKs built before the export is available.
- Kept `scripts/grisp-env.sh` as a compatibility wrapper that now delegates SDK validation and environment export work to `env_utils.sh`, so existing callers benefit immediately without duplicating logic.
- Implemented architecture validation by probing the expected ELF signature with the configured cross compiler and cross `readelf`, then checking every ELF file in both release and overlay trees; if probing fails, the utility falls back to a triplet-to-machine mapping.

## Unexpected Issues And Resolution
- The first implementation of ELF signature probing reused nameref variable names in nested helper calls, which caused circular-reference warnings and empty expected-machine detection.
- Resolved by separating the probe helper's nameref names from the nested parser output names and adding focused wrong-architecture coverage.
- The initial missing-host-command test failed too early because `PATH=""` prevented the utility from sourcing itself (`dirname` unavailable).
- Resolved by using a minimal temporary `PATH` that preserves `dirname` but intentionally omits `cc`, exercising the fast-fail runtime dependency path.
