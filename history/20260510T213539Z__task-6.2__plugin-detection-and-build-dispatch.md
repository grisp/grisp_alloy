## Goal
Implement `alloy build project` plugin detection/build dispatch using `scripts/utils/plugin_utils.sh` as the canonical plugin integration layer, with deterministic detection and support for Erlang and Elixir projects.

## Constraints and design alignment
- No legacy compatibility requirement beyond equivalent end-user functionality.
- Keep architecture aligned with design boundaries: command orchestration in `alloy` command layer, project type logic in plugins.
- Keep implementation maintainable and test-driven.

## Initial observations
- `scripts/commands/build-project.sh` currently resolves SDKs and then fails with a Task 6.2 placeholder in SDK mode.
- Existing `scripts/plugins/project.sh` is legacy-style hardcoded dispatch and not aligned with Task 6.2 refinement note.
- `scripts/utils/plugin_utils.sh` already provides deterministic load/has/call/read primitives suitable for command-layer orchestration.

## Plan
1. Add plugin detection and build dispatch flow to `scripts/commands/build-project.sh`.
2. Use `plugin_load project ...` and deterministic first-match detection.
3. Dispatch plugin `build` action for selected profiles.
4. Add focused command tests that assert Erlang/Elixir detection and unknown-type failure paths.
5. Run targeted tests and relevant gates.

## Implementation summary
- Replaced the SDK-mode Task 6.2 placeholder failure in
  `scripts/commands/build-project.sh` with real plugin-driven execution:
  - load plugins with `plugin_load project ...`,
  - detect project type deterministically from loaded plugin order,
  - dispatch per-profile build via canonical `project_<type>_build`.
- Kept repository-mode behavior as SDK delegation (`alloy build project ...` in
  selected SDK), while SDK mode now performs the project plugin flow directly.
- Aligned builtin project plugins with the canonical plugin-utils function
  naming contract:
  - `project_erlang_detect|build|metadata`
  - `project_elixir_detect|build|metadata`
- Reintroduced `scripts/plugins/project.sh` as the canonical project-domain
  abstraction layer and moved plugin load/detect/build policy into that module,
  so `build-project.sh` consumes project abstraction functions rather than
  owning the plugin iteration logic directly.
- Updated plugin error behavior to use the common command failure path
  (`fail`) for missing tool prerequisites.
- Extended `scripts/tests/test_build_project_command.sh` with SDK-mode
  dispatch coverage using a mock project plugin and unknown-type failure
  coverage.
- Moved legacy bootscheme plugin implementation from active runtime paths
  (`scripts/plugins/bootscheme*`) into `legacy/scripts/plugins/bootscheme*`
  to reduce obsolete plugin surface while preserving historical reference code.
