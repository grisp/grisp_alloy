## Key Decisions
- Treat the current duplication as transitional contract drift rather than two
  intentionally distinct runtime concepts.
- Keep `ALLOY_ROOT_DIR` as the future public runtime/install-root contract:
  the design already assigns it the hook-facing meaning ("root of the alloy
  installation"), Buildroot make handoff already carries it, and hook/docs
  examples resolve paths from it.
- Treat `ALLOY_ROOT` as bootstrap-only or temporary compatibility state during
  migration: the current implementation gives it the same effective value as
  `ALLOY_ROOT_DIR` in both repository and SDK mode, so it is not earning a
  separate public contract.
- Schedule adjacent bootstrap cleanup explicitly instead of folding it into the
  same note: per-command `ROOT_DIR` preambles and transitional wrapper
  compatibility need their own follow-up task once the canonical `alloy ...`
  command paths fully own the flow.

## Unexpected Issues And Resolution
- Investigation surfaced adjacent documentation drift beyond the variable names
  themselves: `docs/01_DATA_DESIGN.md` still describes `script_hook.sh`
  sourcing `common.sh` / hook setup in terms that no longer match the newer
  `hook_common.sh` contract in `docs/03_ALLOY_DESIGN.md`.
- Rather than change the design text without the implementation cleanup, the
  task records that drift as a refinement note on Task 9.2 so the future audit
  has an explicit contract to reconcile.
