# Task 2.5: manifest-tool merge for firmware manifest

## Objective / Outcome

Implemented `manifest-tool merge` so firmware builds can assemble `ALLOY_FIRMWARE_MANIFEST` from one SDK manifest, one or more project manifests, and firmware-level metadata with deterministic integrity checking and repository consolidation.

## Key Decisions

- Reused the existing manifest reader, root validator, integrity verifier, canonical digest code, and file renderer already present in `scripts/tools/manifest-tool` instead of introducing a parallel merge-specific parsing path.
- Kept merge-time failure classes aligned with the existing tool contract:
  - parse errors -> exit 3,
  - structural/input-validation errors -> exit 2,
  - tampered input manifests -> exit 1.
- Consolidated repositories by URL while preserving the first-seen repository entry, suffixing conflicting repository IDs (`name2`, `name3`, ...) and rewriting embedded `repository` / `smelterl_repository` references in the stripped SDK/project payloads.
- Matched the design example for default firmware naming by deriving `firmware_name` from project name/version segments plus SDK product/version, and defaulting `firmware_version` to the SDK product version when not explicitly provided.

## Unexpected Issues / Resolution

- Erlang `binary:split/3` does not accept the `{parts, 2}` option used in the first draft. Replaced those call sites with a small one-split helper built on `binary:match/2` plus `binary:part/3`.
- The merge output path may point into a not-yet-created directory. Updated manifest writes to call `filelib:ensure_dir/1` before writing so `manifest-tool merge --output ...` can create nested targets directly.

## Validation Evidence

- Baseline gate before implementation: `./scripts/tests/gates/baseline.sh` -> PASS.
- Targeted iteration suite: `bash_unit scripts/tests/test_manifest_tool.sh` -> PASS.
- Final gate: `./scripts/tests/gates/full.sh` -> PASS.
- Full gate reported pre-existing non-blocking ShellCheck warnings in legacy `build-firmware.sh` and skipped Smelterl tests because `smelterl/scripts/tests/run_tests.sh` is not present in this checkout.

## Residual Risks

- Firmware-name / firmware-version default derivation is only partially specified in the design docs; the implementation follows the documented example, but the future firmware-orchestrator integration should verify this default against end-to-end artefact naming expectations.

## Planning Refinements

- Added a refinement note to `Task 7.8` documenting that `manifest-tool merge` expands the project-manifest glob internally, requires one `project_root_<id>` per embedded project, and preserves integrity failures as exit 1 distinct from parse/structural failures.
