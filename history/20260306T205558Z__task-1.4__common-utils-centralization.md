## Objective
Implement `scripts/utils/common.sh` as the shared orchestrator utility entry point for guardrails and script preamble helpers, re-exporting `debug_utils.sh` behavior and centralizing reusable helpers currently embedded in the top-level `alloy` script.

## Key Decisions
- Added `scripts/utils/common.sh` as the orchestrator utility entry point that:
  - sets/exports `ALLOY_ROOT` and `ALLOY_ROOT_DIR`,
  - sources and re-exports `scripts/utils/debug_utils.sh`,
  - centralizes shared guardrails/helpers (`fail`, `require_var`,
    `resolve_script_dir`, `source_required_utility`,
    `is_non_negative_integer`, `export_boolean_env`),
  - introduces user-facing output helpers (`print_result`, `print_note`,
    `print_hint`) with ANSI color enabled only when stdout is a terminal and
    `NO_COLOR` is unset.
- Replaced duplicated helper implementations in `alloy` with `common.sh`
  sourcing, while preserving existing CLI behavior and exit-code semantics.
- Added dedicated tests in `scripts/tests/test_common_utils.sh` for failure
  paths, utility loading, symlink-aware path resolution, helper behavior, and
  debug-utils re-export.
- Updated SDK entrypoint fixture setup in `scripts/tests/test_alloy_entry.sh`
  to copy both `common.sh` and `debug_utils.sh` so SDK-mode alloy tests
  execute with the same utility dependencies as real usage.

## Unexpected Issues And Resolution
- `shellcheck` flagged `fixture_loaded` as potentially unassigned in the new
  `common.sh` utility-loading test.
- Resolved by asserting via `${fixture_loaded:-}` so tests remain robust while
  keeping shellcheck clean.
