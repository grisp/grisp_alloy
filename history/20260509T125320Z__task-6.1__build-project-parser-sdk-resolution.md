# Task 6.1 - build-project command parser and SDK resolution

## Scope
- Implemented `alloy build project` command parsing in `scripts/commands/build-project.sh` using `scripts/argparse.sh`.
- Implemented mode-aware SDK resolution for repository and SDK modes.
- Implemented explicit dirty-policy normalization from `--allow-dirty` and `ALLOY_ALLOW_DIRTY`.
- Enforced `ensure_sdk_relocated` for the selected SDK before delegated execution.

## Implementation summary
- Replaced the command wrapper with a canonical command implementation.
- Added parser support for `--help`, `--sdk`, repeatable `--profile`, and `--allow-dirty`.
- Implemented repository-mode SDK selection policy:
  - explicit `--sdk` resolution (directory, archive path, or prefix),
  - auto-selection when unambiguous (single installed SDK or single archive in `artefacts/sdk`),
  - clear ambiguity failure with installed/archive candidate listing.
- Added archive install metadata (`.alloy_sdk_install`) with source archive path and SHA-256 digest.
- Added reinstall-on-change behavior for archive SDK refs (path/hash mismatch triggers reinstall).
- Implemented repository-mode delegation to `${ALLOY_SDK_DIR}/alloy build project ...`.

  - documented auto-selection behavior,
  - documented archive hash-based reinstall behavior,
  - documented repository-mode delegation to SDK-owned command execution.
