# Task 2.6a - artefact-server end-to-end serving tests

## Objective

Added end-to-end coverage for `scripts/tools/artefact-server` so the relocated
tool is exercised through real HTTP requests, real HTTPS requests, and
tar-backed serving.

## Design Grounding

- Read `AGENTS.md`, `docs/00_OVERVIEW.md`, `docs/01_DATA_DESIGN.md`,
  `docs/02_SMELTERL_DESIGN.md`, `docs/03_ALLOY_DESIGN.md`,
  `docs/WORKFLOW.md`, `docs/PLANNING.md`, and `scripts/tests/README.md`.
- Focused design sections:
  - `docs/03_ALLOY_DESIGN.md` §8.7.8 `scripts/tools/artefact-server`
  - `docs/03_ALLOY_DESIGN.md` §3.5 `alloy serve artefacts`

## Initial Investigation

- Existing tests only cover CLI validation and wrapper dispatch.
- There is no current automated coverage for:
  - real HTTP file serving,
  - real HTTPS serving,
  - serving tar members via `<name>/<path>`.

## Key Decisions

- Extended `scripts/tests/test_artefact_server.sh` instead of creating a second
  integration-only file so all artefact-server behavior remains in one place.
- Used real `curl` requests against the live escript on ephemeral ports rather
  than stubbing server internals.
- Used a temporary self-signed certificate generated by `openssl` for the HTTPS
  path and `curl -k` for the client side so the test remains self-contained.
- Covered tar-backed serving through the public `<name>/<path>` route rather
  than calling tar helpers directly.

## Validation

- Baseline before implementation:
  - `./scripts/tests/gates/baseline.sh`
- Focused validation during implementation:
  - `bash scripts/tests/test_artefact_server.sh`
  - `./scripts/tests/run_tests.sh`

## Residual Risks

- Security-pack TLS mode is still covered only by CLI validation, not by a live
  end-to-end test. That remains coupled to the later command/security-pack
  integration work.

## Planning Refinement

- Added a refinement note to `Task 8.3` to extend the new live-server test
  approach to security-pack mode once the documented `secpack` command-contract
  flow is implemented.
