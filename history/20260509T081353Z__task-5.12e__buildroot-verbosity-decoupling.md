# Task Context: 5.12e - Decouple Buildroot verbosity controls from Alloy debug levels

## Objective
Implement command-level Buildroot verbosity controls for `alloy build sdk` via `-D`/`-DD`, decoupled from Alloy `-d/--debug` levels, while preserving reduced default console noise and adding durable Buildroot log capture for all modes.

## Outcome
Implemented the Task 5.12e contract end-to-end in Alloy command flow, Buildroot execution wrapper, helper generation, tests, and docs.

## Key decisions and rationale
- Added a dedicated Buildroot wrapper (`scripts/buildroot/make_buildroot.sh`) as the single SDK Buildroot invocation path.
  - Rationale: preserve one canonical place for console filtering/prefixing, timestamped file logging, and `V=1` behavior.
- Kept default reduced console output for SDK Buildroot invocations (`ALLOY_BUILDROOT_DEBUG=0`) while always writing full timestamped `br.log`.
  - Rationale: preserve current operator UX while improving post-failure diagnostics.
- Separated verbosity controls:
  - `ALLOY_DEBUG` controls Alloy/hook debug logs only.
  - `ALLOY_BUILDROOT_DEBUG` controls Buildroot console and `V=1` behavior.
  - Rationale: removes hidden coupling and makes user intent explicit.
- Made generated `make_alloy` helper default these vars but keep them overrideable at runtime.
  - Rationale: supports workflows like `ALLOY_BUILDROOT_DEBUG=2 ./make_alloy menuconfig`.
