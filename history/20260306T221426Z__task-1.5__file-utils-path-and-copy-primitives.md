## Key Decisions
- Implemented `scripts/utils/file_utils.sh` as a sourced utility module with an
  include guard and `common.sh` bootstrap dependency.
- Implemented design-specified API surface:
  - `normalize_path` (lexical normalization of `.`/`..`, duplicate separators,
    trailing slash handling),
  - `relative_path` (relative derivation for both absolute and relative path
    pairs, with mixed-type validation),
  - `copy_with_exclusions` (recursive copy with exclusion patterns),
  - `merge_directories` (source-over-destination merge wrapper),
  - `make_symlink_relative` (convert link target to relative path from link dir).
- Used `rsync -a --checksum` for deterministic merge overrides and made
  `rsync` an explicit runtime requirement (no fallback copy implementation).
- Added reusable runtime dependency checks in `common.sh`
  (`require_command`, `require_commands`) and integrated execution-path-aware
  `rsync` compatibility checks in `alloy` before Vagrant delegation.
- Added dedicated unit coverage in `scripts/tests/test_file_utils.sh` for all
  public functions and edge/error paths.

## Unexpected Issues And Resolution
- `merge_directories` initially failed to override same-size files when source
  and destination mtimes matched in tests.
- Resolved by enabling `--checksum` in the rsync path so content changes are
  applied even when size/mtime heuristics are identical.

## Design Changes
- Updated `docs/03_ALLOY_DESIGN.md`:

  - `file_utils.sh` `copy_with_exclusions` now documents explicit `rsync`

## Residual Risks / Follow-ups
- `normalize_path` is lexical and intentionally does not resolve filesystem
  symlinks; callers that require symlink-resolution semantics must handle that
  explicitly.
- Runtime compatibility checks currently enforce `rsync`; additional required
  command checks can be expanded as more command/utility surfaces are added.
