## Objective
Align `scripts/argparse.sh` behavior with the design-specified parser contract, with emphasis on `count` option semantics and deterministic option parsing behavior used by command scripts.

## Key Decisions
- Added first-class `count` type support to `scripts/argparse.sh` instead of special-casing command scripts, so all command handlers can share one parser contract.
- Implemented `count` semantics exactly as specified:
  - bare occurrences increment (`-d`, `-dd`, `--debug`),
  - direct value forms assign (`-dN`, `--debug=N`),
  - `--debug <token>` does not consume the next token (next token remains positional).
- Added explicit invalid-value failures for `count` with clear "non-negative integer" errors.
- Added dedicated parser conformance tests in `scripts/tests/test_argparse.sh` to lock behavior for `count`, occurrence tracking (`<VAR>_OPT`), and baseline compatibility for existing `flag/value/accum` types.

## Unexpected Issues And Resolution
- ShellCheck flagged `A && B || C` style in argument-default shift logic (`SC2015`).
- Replaced with explicit `if` blocks to avoid ambiguous control flow and keep touched files lint-clean.
