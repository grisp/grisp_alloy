## Investigation Notes
- Task 2.1 already established shared manifest root parsing/validation, and Task 2.2 added the first public command surface on top of it.
- Task 2.3 needs a reusable integrity pipeline rather than a one-off command implementation, because later `verify`, `create-project`, and `merge` depend on the same canonicalization and digest behavior.
- The design requires order-preserving canonicalization with the root `integrity` field removed before hashing; field reordering must therefore change the digest.

## Key Decisions
- Implemented `manifest-tool hash` directly in `scripts/tools/manifest-tool`
  using the existing manifest root reader, so hash inherits the same parse
  error (`3`) vs structural error (`2`) split already established for
  `validate-root` and `get`.
- Added shared integrity helpers inside `manifest-tool` for:
  - stripping any existing `integrity` section before hashing,
  - rendering the `basic_term_canon` byte stream,
  - computing lowercase SHA-256 hex digests,
  - appending a single normalized `integrity` section.
- Switched Erlang-term machine rendering from `~tp` to `~0tp` for canonical and
  `--format erlang` output so the tool no longer depends on formatter line-wrap
  decisions for long terms.
- Wrote hashed manifests back with a UTF-8 coding header and a compact single
  term representation. This keeps the files valid Erlang term files while
  making the rewritten integrity section deterministic.

## Unexpected Issues And Resolution
- Erlang's default pretty printers (`~p` / `~tp`) insert line breaks for longer
  terms, which would have made the canonical byte stream width-dependent and
  therefore invalid for integrity hashing. The implementation was corrected to
  use the compact formatter `~0tp` for all machine-facing term serialization.

## Residual Risks / Follow-ups
- `manifest-tool` still lacks `verify`, `create-project`, and `merge`, so the
  new canonicalization helpers remain internal to one escript until later tasks
  wire them into the broader manifest lifecycle.
- The rewritten manifest format is deterministic but compact; if a later task
  needs more human-oriented pretty-printing, it must remain strictly separate
  from the canonical byte stream used for integrity hashing.
