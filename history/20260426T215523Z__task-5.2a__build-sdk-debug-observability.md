# Task 5.2a - build-sdk help and debug observability

## Objective

Address user feedback that `alloy build sdk -h` does not make `-d` /
`--debug` discoverable and that `alloy build sdk -d/-dd` does not show useful
additional information during nugget staging.

## Design Grounding

`--debug` is a global Alloy option, but global options are accepted anywhere in
the command line. Command-specific help can therefore mention the relevant
global debug flags without changing parser ownership.

The design already requires orchestrator observability through `log_info` and
`log_debug`; this task applies that rule to the new Task 5.2 staging behavior
and records a workflow reminder so future command tasks do not omit debug
logging.

## Outcome

`alloy build sdk --help` now includes a short global-options section for the
debug and trace flags that are relevant while using the command. This keeps
global option ownership in the top-level parser while making command help less
surprising.

SDK nugget staging now logs high-level progress at `ALLOY_DEBUG=1` and
developer path details at `ALLOY_DEBUG=2`. The level-1 output identifies the
staged repository roles/names and VCS ref; level-2 output includes resolved
stage targets and sync/provenance details.

`docs/WORKFLOW.md` now explicitly requires debug logging to be added or
updated when orchestrator commands and wrappers gain new behavior.

## Validation Notes

The full gate passed, including Smelterl Common Test. ShellCheck still reports
only the pre-existing non-blocking warnings in the legacy `build-firmware.sh`.
