## Investigation Notes
- `scripts/utils/sdk_utils.sh` is still missing.
- `scripts/commands/prepare-sdk.sh` is still a placeholder that exits with an implementation error.
- The current command wrappers that will eventually consume `ensure_sdk_relocated` still defer to legacy top-level scripts, so this task can stay scoped to the relocation utility and explicit `prepare sdk` path.

## Key Decisions
- Implemented the relocation-facing subset of `sdk_utils.sh` now:
  - `check_sdk_relocation`
  - `relocate_sdk`
  - `ensure_sdk_relocated`
- Kept the file aligned with the documented shell utility conventions:
  - explicit source guard,
  - compact interface comments on exported functions,
  - reuse of `file_utils.sh` path normalization for manifest-target resolution.
- Scoped the task to relocation behavior and the explicit `prepare sdk` path,
  leaving pack/embed functions for later build-sdk work where their call sites
  actually exist.
- Implemented `scripts/commands/prepare-sdk.sh` against the finalized utility
  contract instead of leaving the SDK-mode command as a placeholder.

## Unexpected Issues And Resolution
- The copied SDK command fixture in tests initially inherited the repository's
  exported `ALLOY_ROOT`, which made the fixture command think it was still
  running in repository mode.
- Command-fixture invocations now explicitly unset `ALLOY_ROOT` and
  `ALLOY_ROOT_DIR` so the copied SDK command resolves its own SDK root exactly
  like a real unpacked SDK.
- Isolating git config in the earlier VCS tests exposed one subtle dependency:
  the temporary bare remote needed `HEAD` explicitly pointed at `main` so test
  clones had the requested branch available locally. The fixture now sets that
  symbolic ref deterministically.

  `ensure_sdk_relocated` before sourcing SDK context and host tools.
