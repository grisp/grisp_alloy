# Task Context: Task 5.13 - smoke_product language-runtime nugget chain for project builds

## Objective
Implement builtin runtime nuggets and wire smoke_product so generated smoke SDKs are project-build-capable for Erlang and Elixir, without relying on host-installed runtimes.

## Outcome
Implemented and wired new builtin nuggets and package contracts:
- `feature_erlang`
- `feature_elixir` (depends on `feature_erlang`)
- Buildroot package trees:
  - `alloy_erlang`
  - `alloy_rebar3`
  - `alloy_elixir`

`smoke_product` now depends on both runtime features, and builtin registry includes both nuggets.

## Runtime Policy Contract Implemented
- `feature_erlang` exposes `erlang_global_runtime` (default `yes`).
- `feature_elixir` exposes `elixir_global_runtime` (default `yes`).
- Both are normalized from `true/yes/1` and `false/no/0` to Buildroot `y/n` via nugget export scripts.
- Hard constraint enforced: `elixir_global_runtime=true` requires `erlang_global_runtime=true`.
- `erlang=true` with `elixir=false` is allowed.

## Design Choices and Rationale
1. Distinct config keys (`erlang_global_runtime`, `elixir_global_runtime`) instead of a shared ambiguous `global_runtime` key.
   - Avoids cross-feature key collision and makes overrides explicit.
2. Validation in nugget export script.
   - Fails early during config resolution before build execution.
3. Target runtime install split from staging availability.
   - Package install contracts keep target/staging build paths available while allowing rootfs global install policy to be toggled.
